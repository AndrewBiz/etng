# json-output Specification

## Purpose

Контракт JSON-вывода, совместимый с `exiftool -j`, чтобы существующие скрипты и пайплайны работали с etng без изменений.

## Requirements

### Requirement: JSON array response shape
Система SHALL выводить JSON-массив, по одному объекту на входной файл, в порядке аргументов командной строки, и MUST первым полем каждой записи выводить `SourceFile`.

#### Scenario: Два файла
- **WHEN** запрошены два файла в порядке A, B
- **THEN** вывод содержит массив из двух объектов, где первый `SourceFile` указывает на A, второй — на B

#### Scenario: Файл с ошибкой
- **WHEN** один из запрошенных файлов не удалось прочитать
- **THEN** для него выводится объект с полем `Error`, а остальные файлы обрабатываются штатно

### Requirement: System fields parity
Для каждого файла система SHALL выводить системные поля в порядке exiftool: `SourceFile`, `ExifToolVersion`, `FileName`, `Directory`, `FileSize`, `FileModifyDate`, `FileAccessDate`, `FileInodeChangeDate`, `FilePermissions`, `FileType`, `FileTypeExtension`, `MIMEType`, затем теги метаданных.

#### Scenario: Набор системных полей
- **WHEN** выполняется чтение обычного JPEG
- **THEN** в записи присутствуют все перечисленные системные поля в указанном порядке

#### Scenario: Версия совместимости
- **WHEN** вывод разбирается скриптом, ожидающим поле `ExifToolVersion`
- **THEN** поле присутствует и содержит объявленную целевую версию совместимости, одинаковую для всех сборок данной минорной версии

### Requirement: Value formatting compatibility
Система SHALL сериализовать значения в представлении exiftool: даты в формате `YYYY:MM:DD HH:MM:SS±HH:MM`, размеры файлов в человекочитаемом виде (`27 kB`), рациональные величины в виде `1/250`, печатные конверсии для известных тегов (`Orientation: Rotate 90 CW`), целые и дробные — как JSON-числа.

#### Scenario: ExposureTime и FNumber
- **WHEN** в EXIF заданы `ExposureTime = 1/250` и `FNumber = 2.8`
- **THEN** в JSON первое значение выводится строкой `"1/250"`, второе — числом `2.8`

#### Scenario: Размер и дата файла
- **WHEN** файл занимает 27 392 байта
- **THEN** `FileSize` выводится как `"27 kB"`, а `FileModifyDate` — в формате exiftool с часовым поясом

### Requirement: Group prefixes
Система SHALL поддерживать флаги `-G` и `-G1`, формируя имена полей с групповым префиксом (`IFD0:Make`, `System:FileName`) и сохраняя порядок полей, совпадающий с exiftool для того же набора флагов.

#### Scenario: Вывод с -G1
- **WHEN** команда запущена с `-j -G1`
- **THEN** каждое поле, кроме `SourceFile`, имеет префикс группы family 1 (`System`, `File`, `IFD0`, `ExifIFD`, `GPS`, `XMP-dc`), а `SourceFile` остаётся без префикса

### Requirement: Short output flag
Система SHALL принимать флаг `-s` и MUST сохранять имена полей JSON идентичными режиму без флага, как это делает exiftool.

#### Scenario: Флаг -s
- **WHEN** вывод команды с `-j -s` сравнивается с выводом `-j`
- **THEN** JSON-документы идентичны

### Requirement: Numeric mode
Система SHALL поддерживать флаг `-n`, отключая печатные конверсии: размеры, перечисления и рациональные значения MUST выводиться в машинном виде.

#### Scenario: Числовые значения с -n
- **WHEN** команда запущена с `-j -n`
- **THEN** `FileSize` выводится числом байт, `Orientation` — числом, `YCbCrSubSampling` — строкой `"2 2"`

### Requirement: Encoding and escaping
Система SHALL выводить UTF-8 без BOM, экранировать символы по RFC 8259 и MUST сохранять не-ASCII символы в читаемом виде, не превращая их в `\uXXXX`.

#### Scenario: Кириллица в XMP
- **WHEN** XMP содержит заголовок на кириллице
- **THEN** в JSON он присутствует в исходном виде UTF-8

#### Scenario: Кавычки в описании
- **WHEN** значение тега содержит кавычки и перевод строки
- **THEN** JSON остаётся валидным после экранирования

### Requirement: Incremental output
Система SHALL писать записи в stdout по мере обработки файлов, не удерживая весь результат в памяти, чтобы объём памяти не рос линейно с числом файлов.

#### Scenario: Массовая обработка
- **WHEN** обрабатывается 100 000 файлов
- **THEN** пиковое потребление памяти остаётся ограниченным и не пропорционально числу файлов

### Requirement: Valid JSON on warnings
Система MUST сохранять stdout валидным JSON при наличии предупреждений и MUST направлять диагностику в stderr.

#### Scenario: Предупреждение парсера
- **WHEN** при разборе файла возникло предупреждение
- **THEN** stdout успешно парсится как JSON, а текст предупреждения находится в stderr
