# exiftool-fallback Specification

## Purpose

Гибридный режим: делегирование чтения системному `exiftool` там, где собственный парсер не справляется, с бесшовной вставкой результата в общий вывод.

## Requirements

### Requirement: Fallback trigger conditions
Система SHALL делегировать файл системному `exiftool`, если формат не поддерживается собственным парсером или разбор завершился фатальной ошибкой при доступном exiftool; при успешном собственном разборе делегирование MUST NOT выполняться.

#### Scenario: Неподдерживаемый формат
- **WHEN** подан файл формата, отсутствующего в списке поддерживаемых (например, PDF)
- **THEN** файл читается через exiftool, результат попадает в общий JSON-массив

#### Scenario: Собственный разбор успешен
- **WHEN** JPEG разобран собственным парсером без фатальных ошибок
- **THEN** exiftool не вызывается, даже если он установлен

### Requirement: Result merging
Результат делегата SHALL приводиться к общей модели и выводиться на позиции своего файла; служебные поля `SourceFile` и `ExifToolVersion` MUST NOT дублироваться, а при совпадении имён тегов приоритет MUST оставаться за собственным парсером.

#### Scenario: Слияние записи
- **WHEN** часть тегов получена собственным парсером, а часть — делегатом
- **THEN** в записи каждый тег встречается один раз, `SourceFile` один, значения собственного парсера сохранены

#### Scenario: Порядок записей
- **WHEN** в пакете чередуются файлы, обработанные собственным парсером и делегатом
- **THEN** порядок записей соответствует порядку аргументов

### Requirement: Missing exiftool degradation
При отсутствии `exiftool` в `PATH` система MUST NOT падать: неподдерживаемый файл получает запись с `Error`, код возврата 1, а остальные файлы обрабатываются штатно.

#### Scenario: exiftool не установлен
- **WHEN** `exiftool` отсутствует в `PATH` и подан неподдерживаемый файл
- **THEN** запись содержит `Error` с указанием на отсутствие exiftool, код возврата 1

### Requirement: Safe process invocation
Система MUST вызывать exiftool без участия shell, передавая пути аргументами, и MUST корректно обрабатывать имена файлов с пробелами, кавычками и не-ASCII символами.

#### Scenario: Имя файла с пробелами и кавычками
- **WHEN** файл называется `a "b" c.pdf`
- **THEN** делегирование выполняется без ошибок разбора аргументов и без shell-инъекции

### Requirement: Fallback output normalization
Система SHALL приводить JSON делегата к тому же набору флагов, что и собственный вывод (`-G`, `-G1`, `-n`, `-s`, `-q`), и MUST пересобирать служебные поля в едином порядке.

#### Scenario: Делегат с -G1
- **WHEN** команда запущена с `-G1` и файл обработан делегатом
- **THEN** его поля имеют групповые префиксы в том же стиле, что и у файлов, прочитанных собственным парсером

### Requirement: Fallback diagnostics
Система SHALL сообщать в stderr о каждом факте делегирования и о причине, не засоряя stdout, и MUST подавлять эти сообщения при `-q`.

#### Scenario: Сообщение о делегировании
- **WHEN** файл передан exiftool в режиме по умолчанию
- **THEN** в stderr появляется строка с путём файла и причиной делегирования, stdout остаётся валидным JSON
