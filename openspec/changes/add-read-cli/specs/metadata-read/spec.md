# Spec Delta

## Purpose

Чтение метаданных изображений из популярных форматов и приведение их к единой типизированной модели, пригодной для сериализации в exiftool-совместимый JSON.

## ADDED Requirements

### Requirement: Format detection by content
Система SHALL определять формат файла по сигнатуре содержимого, а не по расширению, и MUST отклонять файлы, сигнатура которых не распознана, как неподдерживаемые.

#### Scenario: JPEG без расширения
- **WHEN** на вход подан файл JPEG с именем `photo.bin`
- **THEN** формат определяется как JPEG, а в выводе присутствуют `FileType: JPEG` и `FileTypeExtension: jpg`

#### Scenario: Неизвестная сигнатура
- **WHEN** на вход подан текстовый файл
- **THEN** он помечается как неподдерживаемый без паники и без разбора содержимого

### Requirement: EXIF, IPTC, XMP and GPS extraction
Система SHALL извлекать теги EXIF, IPTC, XMP и GPS из поддерживаемых контейнеров и MUST сохранять принадлежность каждого тега к исходному источнику для группировки в выводе.

#### Scenario: JPEG с EXIF и XMP
- **WHEN** файл содержит блоки EXIF и XMP с разными наборами тегов
- **THEN** в результате присутствуют теги обоих источников, и каждый отнесён к своей группе

#### Scenario: Отсутствие GPS
- **WHEN** в файле нет GPS-блока
- **THEN** GPS-теги в результат не добавляются, остальные теги извлекаются штатно

### Requirement: Supported containers
Система SHALL читать метаданные из JPEG, HEIC/HEIF, TIFF, DNG, CR2 и NEF и MUST выдавать для каждого из них общий набор системных полей файла вместе с извлечёнными тегами.

#### Scenario: HEIC-контейнер
- **WHEN** на вход подан HEIC-файл с EXIF
- **THEN** EXIF-теги извлекаются, а `FileType` равен `HEIC`

#### Scenario: DNG и TIFF
- **WHEN** на вход подан DNG-файл
- **THEN** он разбирается как TIFF-контейнер, и в результате есть и TIFF-теги, и EXIF-теги

### Requirement: Basic MakerNotes support
Система SHALL извлекать подмножество MakerNotes для Canon, Nikon и Sony, помечая такие теги семейством групп `MakerNotes` (family 0) и группой вендора (family 1); нераспознанные вендорские блоки MUST NOT приводить к ошибке чтения файла.

#### Scenario: Canon MakerNotes
- **WHEN** файл содержит MakerNotes Canon с известными тегами
- **THEN** распознанные теги попадают в вывод с префиксом группы `Canon` при `-G1` и семейством `MakerNotes` при `-G`

#### Scenario: Неизвестный вендор
- **WHEN** MakerNote-блок принадлежит неподдерживаемому вендору
- **THEN** остальные метаданные извлекаются, а блок пропускается с предупреждением в stderr

### Requirement: Broken and hostile file tolerance
Система SHALL возвращать частичный результат и диагностику для повреждённых файлов и MUST NOT паниковать, зависать или исчерпывать память при разборе враждебных входных данных.

#### Scenario: Обрезанный JPEG
- **WHEN** JPEG обрезан внутри сегмента EXIF
- **THEN** команда завершается с кодом частичной ошибки, выводит извлечённые до обрыва теги и пишет предупреждение в stderr

#### Scenario: Циклические смещения IFD
- **WHEN** в EXIF указаны циклические смещения IFD
- **THEN** разбор прекращается по лимиту глубины без зависания и без OOM

### Requirement: Value normalization
Система SHALL нормализовать значения тегов к типизированным величинам (число, строка, дата, рациональное число) и MUST сохранять исходное строковое представление там, где тип не определён.

#### Scenario: Дата съёмки
- **WHEN** в EXIF присутствует `DateTimeOriginal`
- **THEN** значение нормализуется как дата и далее сериализуется в формате exiftool

#### Scenario: Неизвестный тип тега
- **WHEN** тег имеет неопределённый тип
- **THEN** значение выводится как строка без потери байтов

### Requirement: Read-only access
Система MUST открывать входные файлы только на чтение и MUST NOT изменять их содержимое, mtime или расширенные атрибуты.

#### Scenario: Файл только для чтения
- **WHEN** на вход подан файл с правами `r--`
- **THEN** чтение выполняется успешно, а хеш и mtime файла после запуска не меняются

### Requirement: Deterministic tag set
Для одинакового файла и одинакового набора флагов система SHALL выдавать один и тот же набор тегов в одном и том же порядке при повторных запусках и на разных машинах.

#### Scenario: Повторный запуск
- **WHEN** одна и та же команда выполняется дважды на одном файле
- **THEN** JSON-вывод побайтово идентичен, за исключением полей времени доступа к файлу
