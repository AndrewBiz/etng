# Proposal

## Why

Одиночный файл читается за ~35 мс против ~102 мс у exiftool — всего 2.9×, тогда как батч ускоряется в 169×. Причина — ленивый разбор всех 31 942 строк `tags.tsv` (4.5 МБ) при первом обращении к таблицам: скрипт, вызывающий `etng` на каждый файл, платит эту цену заново.

## What Changes

- Таблицы тегов индексируются один раз по group 1 и table без разбора всех `TagDef`; разбирается только группа, к которой реально обратились, и кэшируется.
- Печатные конверсии хранятся как срез исходной строки и разбираются по требованию, без `Vec` на каждый тег.
- Проверка имён тегов в CLI (`-TAG`, `-GROUP:TAG`) сканирует сырые строки, не материализуя таблицы.
- Наблюдаемое поведение, JSON, коды возврата и порядок вывода не меняются; корректность подтверждается существующим golden-корпусом.
- **BREAKING**: нет.

## Capabilities

### New Capabilities

Нет: изменение чисто производительное, внешние требования не меняются (`skip_specs: true`).

### Modified Capabilities

Нет.

## Impact

- `crates/etng-tags` — внутренняя структура `Tables`, API поиска сохраняется.
- `crates/etng-cli` — проверка выбранных тегов без полной загрузки таблиц.
- `crates/etng-core` — без изменений API; вызовы `find_*` продолжают работать.
- Тесты: новые проверки ленивости и сохранения семантики неоднозначных таблиц (`Exif::Main` принадлежит нескольким группам).
- Бенчмарки: `tests/bench.py`, `BENCHMARKS.md`; цель — одиночный файл <10 мс (растяжимо <5 мс), батч не медленнее.
