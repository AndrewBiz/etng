# Design

## Context

ICC-профиль: 128-байтный заголовок (`acsp` по смещению 36), затем таблица
тегов (`count` + записи signature/offset/size). Строки бывают `desc` (v2),
`mluc` (v4), `text`; XYZ — s15Fixed16.

Профили лежат в JPEG APP2 (`ICC_PROFILE\0` + seq/count + данные), TIFF-теге
`0x8773` и HEIC-боксе `colr` с сигнатурой `prof`.

## Decisions

### D1. Сборка JPEG-чанков
Чанки складываются по sequence (1-based) и проверяется, что все count на месте;
иначе профиль не выводится.

### D2. Строгий compare
ICC-теги убраны из `KNOWN_PREFIXES`; снимки уже содержали ICC, поэтому
`xtask compare` теперь проверяет их значение, а не игнорирует.

### D3. Форматирование
XYZ — `%.5f` с обрезкой нулей; версия — BCD-ниблы (`2.10` → `2.1.0`);
TRC — `Value::Bytes`, чтобы работал `-b`; enum-подписи маппятся в текстовые
названия exiftool.

## Risks / Trade-offs

- **[Неизвестные сигнатуры]** → `Unknown (sig)`; профиль всё равно читается.
- **[mluc-локаль]** → берётся первая запись, обычно enUS.
- **[Экзотические типы]** → пропускаются без ошибки.
