# Design

## Context

Даты EXIF — 20-байтные ASCII. Если тега нет, нельзя просто дописать значение:
нужен новый IFD-entry. Перестраивать существующий IFD рискованно (offset'ы
значений и thumbnail). Вместо этого создаётся новый ExifIFD в конце TIFF, а
указатель `0x8769` в IFD0 переводится на него.

## Decisions

### D1. Append-only IFD
Старые записи ExifIFD копируются байт-в-байт; новые даты добавляются с
offset'ами после нового IFD. Старые offset'ы значений остаются валидными.

### D2. Обновление IFD0 pointer
Указатель `0x8769` в IFD0 переписывается на новый offset. Для JPEG
пересчитывается длина APP1 (`2 + 6 + TIFF`), файл перестраивается.

### D3. Существующие даты
При смешанном запросе (часть тегов есть, часть нет) существующие значения
патчатся в новом TIFF, отсутствующие добавляются.

### D4. Границы
`ModifyDate` в IFD0 при отсутствии не вставляется; HEIC/CR3/MOV не входят.

## Risks / Trade-offs

- **[Размер файла]** → APP1/TIFF растёт на ~100 байт.
- **[Старый ExifIFD]** → остаётся орфанным блоком; безопасно, но не компактно.
- **[XMP/IPTC digest]** → exiftool может предупредить о несинхронном digest;
  значения XMP/IPTC не меняются.
