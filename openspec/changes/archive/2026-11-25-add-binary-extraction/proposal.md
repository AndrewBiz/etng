# Proposal

## Why

`etng` повторяет текстовое поведение `exiftool`, но не умеет отдавать бинарные значения: миниатюры, превью RAW и произвольные `undefined`-блоки сейчас видны только как заглушка `(Binary data N bytes, use -b option to extract)`. Из-за этого нельзя достать встроенный JPEG, а `IFD1:ThumbnailImage` остаётся задокументированным расхождением.

## What Changes

- Добавляется флаг `-b`/`--binary`, работающий в текстовом и JSON-режимах.
- В текстовом режиме значения пишутся в stdout без разделителей: скаляры — непреобразованным значением (`Orientation` → `1`), бинарные теги — сырыми байтами; порядок выбранных тегов задаёт порядок `-TAG`.
- В JSON-режиме (`-j -b`) бинарные значения кодируются строкой `"base64:<data>"`; остальные поля не меняются.
- Из IFD1 извлекаются реальные байты миниатюры (`ThumbnailImage`), из CR2 — реальное превью (`PreviewImage`) вместо нулей.
- Диагностика и предупреждения остаются в stderr; коды возврата не меняются.
- Fallback на системный exiftool не используется для получения бинарных значений (ограничение фиксируется в документации).

## Capabilities

### New Capabilities

- `binary-output`: извлечение и вывод сырых значений, base64 в JSON, порядок и разделители.

### Modified Capabilities

- `metadata-read`: встроенные изображения (миниатюра IFD1, превью CR2) материализуются как байты, а не заглушки/нули.

## Impact

- `crates/etng-core`: `ReadOptions`, извлечение миниатюры/превью, JSON-эмиттер.
- `crates/etng-cli`: разбор `-b`, отдельный потоковый writer для сырого вывода.
- Тесты: unit на base64 и извлечение, CLI-тесты на raw/JSON, сравнение байтов с exiftool в `xtask compare`.
- Документация: `README.md`, `docs/divergences.md` (убрать `IFD1:ThumbnailImage` из известных), `BENCHMARKS.md` не затрагивается.
